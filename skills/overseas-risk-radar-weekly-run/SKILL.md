# overseas-risk-radar-weekly-run

## When to use

当用户要求重跑 / 重新搜集 / 更新 / 发布「海外风险雷达周报」时触发，尤其出现以下表述：

- "重新跑一遍周报" / "搜集整合上周到现在的新内容，推送新一期"
- "按决策导向口径" / "按影响面重搜" / "过一遍信号研判"
- "写入腾讯文档" / "生成周报和明细" / "风险雷达周报"
- 想对一批原始采集条目（新闻/GNews/社媒/RSS）做"是否值得进周报"的快速研判

## 工作流程总览

```
[1] 采集原始信号（WebSearch / GNews / RSS / 监管页 / 用户粘贴的条目 batch）
        │
        ▼
[2] ★ 信号研判层（决策导向 · 主闸）── references/signal_screening_prompt.md
        │   对每条问："它会不会改变 PM/宿主对【某款游戏/某类题材/某个投放动作】的决策？"
        │   产出严格 JSON {"results":[...]}，只收 pass_review:true 且 relevance≥0.6
        ▼
[3] 跨期去重（对照 Issue 1–N 基线，event_key 聚合）
        │
        ▼
[4] 影响面评估（优先渠道级/平台级宽影响，子集级窄影响不凑数）
        │
        ▼
[5] 区域分布 + 诚实留白（三区均衡，无信号区留空）
        │
        ▼
[6] 生成周报 MD + CSV（消费 pass_review:true 的 JSON 项，字段映射见下）
        │
        ▼
[7] 可选同步腾讯文档（独立智能文档）；校验后回复 + 写记忆日志
```

## 第 2 步 · 信号研判层（主闸，最重要）

这是整个流水线的**第一道筛**。规则全部来自 `references/signal_screening_prompt.md`，要点速记：

- **唯一决策标准**：会不会改变 PM/宿主对某款游戏 / 某类题材 / 某个投放动作 的决策？不改 → 丢。
- **反例必丢**：市场规模综述、展会流水账、宏观大盘、出口数据、宽泛行业报告、无法落到"具体游戏/题材/玩法/政策条款/禁忌"的内容。
- **四类有效主题（带颗粒度门槛）**：
  1. `compliance` 合规政策——必须落到与游戏直接相关的**具体条款**（分级/内容审查/数据隐私/支付/广告/未成年/平台准入）；仅口号 → 丢。
  2. `culture` 宗教文化禁忌——必须指向"哪些题材/符号/配色/角色设定要规避"；泛泛介绍 → 丢。
  3. `hotspot` 区域热点——必须指向"某款游戏爆款机会"或"某事件引发对某题材/玩法的监管或抵制"。
  4. `trend` / `ops` 内容·玩法·社媒趋势 / 宿主运营——必须指向**具体**玩法/题材/KOL/平台政策变化；泛泛短视频统计 → 丢。
- **产出严格 JSON**（每条含 relevance / pass_review / drop_reason / nature / topic / compliance_clause / targets / affected_games / level / fact / impact / action / summary_zh / event_key）。
- **硬性原则**：
  - 宁缺毋滥，宁可漏报不可错报。
  - **微信小游戏 = 轻量休闲、HTML5、即点即玩为主。AAA 主机端游（Diablo、Switch、PS5 大作）不在适用范围 → relevance ≤ 0.3**，仅当事件能间接影响小游戏合规/选品/投放（平台政策、未成年保护法等）才纳入。
  - 事实(fact)与研判(impact/action)严格分离。
  - 不臆测、不夸大、不做行业大盘分析。
  - 严格按 id 顺序逐条研判，不从其它条目串接。
- **风险等级**（仅下沉 CSV 内部字段，正文不展示图标）：`high`🔴法律红线/下架封号罚款/重大禁忌/大规模负面舆情（社媒单一来源不给 high）；`mid`🟡政策苗头/潜在敏感点/竞品趋势；`low`🟢一般参考/长期观察。

> 直接把 `references/signal_screening_prompt.md` 当作分类器 prompt 发出，再把待研判 batch 注入 `=== 任务输入 ===` 之后即可。已研判示例见 `references/screening_example.md`（4 条韩国社媒 → 全丢，演示去噪）。

## 第 3 步 · 跨期去重

- 生成前必须读取：① 第 1 期基线文件（6 事件）→ ② 工作目录内最新的 `weekly_report_YYYYMMDD_*.md` + 同名 CSV → ③ `MEMORY.md`。
- 用研判 JSON 的 `event_key` 与基线做聚合比对。同一事件无新增事实 → 禁止重复；有新增事实（正式生效 / 新处罚 / 裁决推进）→ 只写新事实。
- `references/dedupe_baseline.md` 是已覆盖主题的**快速索引**；**权威源永远是本地 MD/CSV 文件，索引可能滞后，以实际文件为准**。
- 长期机会 / 中期风险：同一主题至少间隔 4 周才可复现，除非有官方更新、数据更新或明确影响升级。

## 第 4 步 · 影响面评估（影响广度）

- 优先收录**打在所有发行方底盘**上的**渠道级 / 平台级 / 营收级**信号：应用商店政策、反垄断裁决、数字税、未成年人立法、年龄验证强制、支付/退款规则。
- 这类事件不挑"是否注册 / 是否含 AI / 是否含社交"，影响面 = 全市场全部游戏。
- **子集级窄影响事件**（仅打"未注册平台""含 AI 功能""含社交互动"的子集）价值低于渠道级，仅在无更好宽影响信号时作为补充；**不要为凑区域 / 数量放低质量信号**。

## 第 5 步 · 区域分布 + 诚实留白

- 三区（东南亚 / 日韩 / 西欧）尽量均衡覆盖，但**不为凑数填充弱相关 / 旧闻**。
- 某区本窗口无达标的独立风险信号 → 该区**留空**（正文或内部说明注明"无新增情报"），不把旧事件 / 弱相关项塞进去。

## 禁用字段 & 必含字段（呈现规则）

**正文禁止（遇到即改写/删除）：**
- `响应时序`、`对宿主 PM 的影响`、`处理优先级`、`高/中/低`、`🔴🟡🟢` 风险等级
- `全球平台` / `全球游戏生态` / `Roblox 生态` / `YouTube 生态` 等独立分类块
- 采集漏斗统计、来源覆盖表、剔除说明、watchlist / 内部跟踪
- 跨期对比字眼（`上期` / `本期新增` / `相比上周` / `延续上次`）
- 时间窗口规则表述（`过去 7-14 天` / `90 天内` / `距今 X 天`）

**正文必含：**
- `可能影响的宿主：AXIS、Chikii…`（一行清单；无法明确映射写 `人工判断确认`）
- `行动建议`（具体动作 + 产品/页面 + 建议时限；禁"核查/评估"泛泛）
- 来源链接（≥1 可点击；权威/合规事件优先 ≥2 独立来源交叉验证）

**时效规则仅内部使用**：未来生效法规若有"宣布生效 / 显著推进"动作可纳入，但"例外纳入"的理由只在内部判断，不外露规则表述。

## JSON 字段 → 周报字段映射

| 研判 JSON 字段 | 落到周报的位置 |
|---|---|
| `summary_zh` | 区域热点一句话 / 事件块标题参考 |
| `fact` | `**1. 事实**`（只写客观事实，含时间） |
| `impact` | `**3. 影响链路与动作价值**`（研判，与事实分离） |
| `action` | `**4. 行动建议**`（动词开头、可动手） |
| `targets` | 推导 `**2. 可能影响的宿主**` + CSV `targets` 列 |
| `affected_games` | 标题/题材关键词（如"含宗教符号题材""休闲解谜小游戏"） |
| `nature` / `topic` / `compliance_clause` / `level` | **仅下沉 CSV 内部字段**，正文不展示风险图标与"高/中/低" |
| `event_key` | 跨期去重聚合键 + CSV id |

## 周报结构（正式版）

严格按 `references/report_template.md` 输出。要点：
- 标题：`# 海外风险雷达周报｜正式第 N 期（YYYY.MM.DD – YYYY.MM.DD）`
- 顶部 2 行引用块：① 面向宿主 PM 的高相关风险/机会推送，按区域整合呈现；② 本期筛选主尺一句话说明（如"以「影响面」为尺，仅收录通过决策导向研判的条目"）。
- `## 一句话看全局`：每条一地区/一主题，**现象 + 影响一句话**浓缩，不堆砌数据。
- 区域分块（顺序固定）：`## 渠道级信号（跨东南亚/日韩/西欧）`（如有全局平台政策）→ `## 东南亚` → `## 日韩` → `## 西欧`。每区下按 `### 国家｜【领域】标题` 组织事件。
- 每个事件块结构：**区域热点一句话** → `**1. 事实**` → `**2. 可能影响的宿主**` → `**3. 影响链路与动作价值**` → `**4. 行动建议**` → `**5. 来源（多来源交叉验证）`。
- `## 区域爆款游戏趋势`：三区各一条品类趋势，每条含 `**2. 小游戏典例**` + `**3. 小游戏可引入方向**`（详见 `references/category_trend_template.md`）。
- 文末页脚：`> 数据来源：… 下期更新：YYYY.MM.DD`

## 执行步骤

1. **读真源**：读最新主 Prompt（背景/源清单）、`MEMORY.md`（运营规则）、最新本地周报 + CSV（本期候选与去重上下文）、`references/dedupe_baseline.md`。
2. **确认周期**：默认截至今天的本周；若同日文件已存在，新建 `_v2` / `_v3` 版本号，不覆盖。
3. **采集候选**：按三区 × 主题并行 WebSearch；优先官方/监管页、平台官方、权威主流媒体、头部行业媒体。社媒仅作信号，不单独作为最终证据。用户也可直接粘贴一批原始条目 batch 进入第 4 步研判。
4. **★ 信号研判（主闸）**：把原始条目套 `references/signal_screening_prompt.md` 产出 JSON，**只收 `pass_review:true` 且 `relevance≥0.6`**。
5. **跨期去重 → 影响面评估 → 区域分布**：依前述步骤收敛，形成本期入选集。
6. **生成产物**：`weekly_report_YYYYMMDD_正式第N期_vN.md` + `risk_items_YYYYMMDD_正式第N期_vN.csv`（CSV 含完整内部研判字段：nature/topic/compliance_clause/targets/level/relevance + 漏斗数量、来源覆盖）。
7. **腾讯文档**：仅当用户明确要求才同步；每期独立智能文档（API 不支持在已有文档内新建子页）。连接器 disconnected 时，先交付本地 MD/CSV 并说明未同步，不伪造链接。
8. **校验后回复**：Grep 正文禁用词；确认含 `可能影响的宿主`、无漏斗泄露；交付本地附件并打开主报告；追加项目记忆日志。

## 腾讯文档同步规则

- 正式推送库：`海外风险雷达正式推送库` 智能文档（第 1 期）。第 2 期起每期独立智能文档。
- 返回链接须保留工具原 URL 并追加 `?_fid=<file_id>`。
- 用户指认某版为"正式第 N 期基线"时，**回复前**把确切本地文件名、腾讯文档 file id/link、基线指令写入 `MEMORY.md`。

## Pitfalls（踩坑记录）

- 不要覆盖已有周报，除非用户明说。
- 不要把旧背景当最终事件凑区域——某区本窗口无信号就留空。
- 不要把 Roblox / UGC / 小游戏平台事件单列「全球」分类，必须归并到最强区域。
- 不要引入旧 heading、优先级表、风险图标、旧字段名；整合旧版本时先 Normalize 到当前模板。
- 正文不外露时效窗口阈值。
- 社媒帖不作为最终证据，除非 ≥2 独立来源交叉验证；单一社媒来源不得给 `high`。
- 腾讯文档 URL 必须带 `_fid=<file_id>`。
- 向智能文档 smartcanvas 追加时，插入内容不要以 `---` 开头、避免 `>` 开头的引用块（MDX 转换器会当 YAML frontmatter 报错）。
- 监管源页若只返回 bot/验证页，不得作为已验证来源引用。
- 影响面评估时，子集级窄影响事件不得排在渠道级宽影响事件之前；已覆盖主题（如第 4 期 PEGI 16 与本期 DFA 是"分级落地 vs 立法路径"不同角度，可并存，但需注明角度差异避免重复感）。
- 韩国 loot box 概率公示在 Issue 1 已是"高敏项"泛述，任何"点名具体游戏执法"新动作属同主题——按跨期去重规则需间隔 ≥4 周或重大新进展才复现。
- **微信小游戏范围边界**：AAA 主机/端游（Diablo、Switch、PS5）虽是游戏新闻但不在小游戏适用范围，研判时 relevance ≤ 0.3 应直接丢弃，除非事件本身是平台政策/未成年保护法等可间接影响小游戏的合规/选品/投放。
