# 游戏商业视觉 SOP（Vertical Poster Adapter）

> **定位**：这是 `narrative-driven-cover-variants.md` 的竖版海报 Adapter。只解决**海报图**问题，与横向封面 Adapter 并列，共同归属游戏商业视觉 SOP 控制台。
> **交互页面**：`wiki/sources/game-poster-learning-sop/cover.html`（Format Adapter 切换器，同时包含横向封面和竖版海报两套选项）  
> **核心约束**：学习和生成时必须把 **图形比例层** 与 **表现因素层** 分开。比例决定结构，表现因素决定类型气质。  
> **使用场景**：后续周期性喂海报图素材时，用本文持续沉淀新模式；每次收到用户反馈后，用「反馈进化协议」升级选项池、比例阈值或反模式。

## 0. 素材准入清单（生成图触发前必检 ⭐ 强约束）

**触发条件**：当用户要求「生成游戏封面图 / 海报图 / 商业视觉」时，AI 必须先检查以下 4 项素材是否齐全；**任一必选项缺失，必须先停下来向用户索取，不允许进入比例层 / 表现层 / 叙事层选项流程**。

| # | 类型 | 字段名 | 必选 | 用途 |
|---|------|--------|:---:|------|
| 1 | 文本字段 | **游戏名字** | ✅ 必选 | 用于 DNA 卡 / 标题排版 / Logo 安全区 / 玩法 Fidelity 锚点；AI 不通过图像识别去猜，必须用户提供 |
| 2 | 文本字段 | **广告语 / Tagline** | ⬜ 可选 | 用于副标题 / 底部商业信息；缺失则在 Brief 中显式标 `null`，不要自己编造 |
| 3 | 正方形图 | **游戏 ICON** | ✅ 必选 | 用于角色资产剥离起点（Memory 57615156）/ 风格 DNA 比对锚 / Logo 视觉一致性；正方形比例（1:1） |
| 4 | 长方形图 | **游戏画面截图** | ✅ 必选 | 用于真实玩法可视化锚定 → `gameplay_lock` / 玩法 Fidelity 自检（Step 8）；横向比例任意（16:9 / 5:3 / 3:2 等） |

### AI 行为协议

#### 收到生成需求时的标准开场（必须执行）

```text
在生成之前，请先确认提供以下素材：

  ✅ 必选 1：游戏名字（文本）
  ⬜ 可选  ：广告语 / tagline（如有）
  ✅ 必选 2：游戏 ICON（正方形图）
  ✅ 必选 3：游戏画面截图（长方形图）

【为什么需要】
- 游戏名字 → 我无法靠看图识别游戏；必须由你提供，避免我用训练先验猜测
- ICON → 角色资产剥离 / 风格 DNA 锚定起点
- 画面截图 → 玩法 Fidelity 自检的基准（防止把三消画成桌游这类高危误导）

请补齐素材后我们再进入构图与风格选项。
```

#### 完整性检查表（Step 0 前置门）

| 项目 | 检查 | 缺失时行为 |
|------|------|-----------|
| 游戏名字 | 文本是否给出？ | 停下来索取，不接受"随便起一个"或"先不重要" |
| 广告语 | 文本是否给出？ | 可继续，但 Brief 中 `tagline: null` 显式标注 |
| ICON | 是否提供 1:1 比例图？ | 停下来索取；如果用户只给了横图，明确指出"我需要的是 ICON" |
| 截图 | 是否提供横向截图？ | 停下来索取；如果只给海报图，明确指出"我需要的是真实游戏内截图，不是宣传海报" |

#### 反模式（禁止）

- ❌ 用户没给游戏名 → AI 凭训练先验猜测"这看起来像 XX 游戏"
- ❌ 用户没给 ICON → AI 直接用泛化的 DNA 卡进入选项流程
- ❌ 用户没给截图 → AI 跳过玩法 Fidelity 自检，假设玩法类型
- ❌ 用户给的"截图"其实是另一张海报 / Key Art → AI 不指出差异，直接当真实玩法证据使用

#### 横向封面 vs 竖版海报 — 同一套准入

本清单**对横向封面图、竖版海报图都生效**。Format Adapter 切换不改变素材准入要求。

### 0.1 输入素材 ≠ 输出画面元素（2026-05-29 实战修正 · 强约束）

**本次失败反馈**：`Tricky Puzzle` 首轮 GPT Image 生成质量显著下降，并且封面图中出现了游戏 ICON。用户明确反馈：**封面图里出现游戏 ICON 是绝对不能接受的表现**。

因此补充一条硬规则：

> `ICON` 和 `游戏截图` 是 **reference-only inputs**，只用于分析 DNA / 玩法 / UI 风格；**默认禁止作为画面元素被画进封面或海报**。

#### 输入素材用途边界

| 素材 | 正确用途 | 默认禁止 |
|------|----------|----------|
| 游戏名字 | 用于标题 / DNA 命名 / Brief 字段 | 不允许 AI 改名、扩写成假官方标题 |
| 广告语 | 用户提供时才可放入副标题 | 未提供时不允许编造 tagline |
| ICON | 只用于角色资产剥离、角色身份、色彩 / 线条 / UI DNA 分析 | **禁止在封面图 / 海报图中出现 app icon、小方形图标、商店 icon、桌面图标、购买按钮、下载按钮** |
| 游戏截图 | 只用于玩法机制、真实 UI、角色/场景风格分析 | 禁止直接复刻截图 UI、关卡菜单、底部导航、截图外框、手机状态栏 |

#### Prompt 负面锁（每条生成 prompt 必带）

```text
Do not include any purchase button, download button, app store badge,
rating button, share button, or call-to-action button in the image.
Use the provided icon and screenshots only as reference for art style,
character identity, UI color language, and gameplay fidelity.
```

#### 例外

只有当用户**明确要求**做「强转化买量广告卡」且说要展示购买按钮 / download button 时，才允许把按钮作为画面元素。默认的 **横向封面图 / 竖版海报图** 一律禁止出现任何按钮 UI。

## 0.7 全局策略复用：4 杠杆差异化矩阵对竖版同样有效

> **重要修正（2026-05-29）**：4 杠杆差异化矩阵原本只在 Core 文档的「横向封面 Adapter」章节出现，造成误解为"只对横向有效"。事实是：**4 杠杆是「同 DNA 下做 N 个方案如何拉开差异」的抽象数学，跨容器、跨题材通用**。

### 竖版海报怎么用 4 杠杆

竖版海报多方案分叉时，**仍然按 4 杠杆 + 强制差异化规则做**：

| 杠杆 | 在竖版海报里的对应 | 备注 |
|---|---|---|
| **L1 镜头** | 视觉动线（top-title-to-hero / diagonal / giant-shape / depth-tunnel …） + 镜头机位 | 与构图模板有交叠但更抽象 |
| **L2 光线** | 表现层 lighting（边缘光 / 逆光剪影 / 中心爆光 / 顶部大光源 / 冷暖对撞 …） | 与表现层 lighting 字段一致 |
| **L3 场景** | 海报背景的"世界容器"（废墟 / 城市 / 王座 / 棋盘 / 雪山 …） | ⚠️ 强题材依赖，必须按当前游戏题材重写取值池 |
| **L4 占比** | hero_weight + 装饰信息密度（小人物 / 均衡 / 主导 / 群像） | 与比例层 hero_weight 字段一致 |

### 强制差异化规则（不可妥协）

> **每两个竖版海报方案，至少错开 3 / 4 个杠杆**，否则视为「伪分叉」必须返工。

为什么是 3 不是 2：实证只错开 2 个杠杆时，人眼扫过去仍觉得"是同一张海报换动作"。  
为什么是 3 不是 4：4 个全错开会失去 DNA 一致性，跨方案没有家族感。

### 高危值通用模式（防玩法误导）

无论横向竖版，以下值组合最容易触发玩法误导：

- **L1 严格正交俯视网格** → 暗示桌游 / 棋类
- **L1 过肩瞄准准星** → 暗示射击 / FPS
- **L3 明确品类符号场景物**（棋盘 / 牌桌 / 球桌 / 转盘 / 老虎机） → 直接被认成对应品类
- **L4 玩法元素以"精确网格阵列"排布** → 暗示策略 / 桌游

竖版海报的 Step 8 玩法 Fidelity 自检必须扫这一遍。

### 与本文档已有内容的关系

- §3「8 个常用构图模板」= 比例 archetype 池，与 4 杠杆**互补不替代**：archetype 锁定大结构（标题/主体/留白比例），4 杠杆负责"在同一 archetype 内的不同方案如何错开"
- §4「视觉动线选项」≈ L1 杠杆的子集
- §5「表现因素层」中的 lighting ≈ L2 杠杆
- §6「叙事变量」与 4 杠杆**正交**：4 杠杆管视觉差异化，5 故事维度管叙事差异化，两层都要拉开

### 控制台中的位置

HTML 控制台已把 4 杠杆策略提升为**全局 section**（紫色 ★ 标记），位于准入门下方、Adapter 切换器之后，对横向 / 竖版都可见。

## 1. 第一原则：比例层与表现层分离

任何海报学习先拆成两张表。

### 1.1 图形比例层（先看这个）

只回答：

```text
谁占多大？
放在哪里？
谁压谁？
视线怎么走？
留白在哪里？
前中后三层各占多少？
```

不要先讨论颜色、字体、题材、质感。

### 1.2 表现因素层（后看这个）

再回答：

```text
它属于什么类型气质？
主色 / 辅色 / 点睛色是什么？
字体人格是什么？
光影怎么制造情绪？
纹理如何统一成品感？
背景如何讲故事？
商业信息如何不抢主视觉？
```

### 1.3 强制顺序

```text
Step A. 先判定容器比例
Step B. 再判定图形占比
Step C. 再判定视觉动线
Step D. 最后才判定色彩 / 字体 / 光影 / 质感 / 文案
```

## 2. 图形比例层：竖版海报核心变量

### 2.1 画幅选项

| 选项 | 适用 | 备注 |
|---|---|---|
| `9:16` | 手机端投放 / 小红书 / 竖屏资产 | 冲击力最强，最适合大标题 + 大角色 |
| `2:3` | 传统电影海报 / 游戏主视觉 | 情绪稳定，适合暗黑叙事和极简剪影 |
| `3:4` | 商店页 / 角色卡 | 信息密度适中 |
| `4:5` | 社媒流 / Feed 广告 | 更接近内容流，适合商业活动图 |

### 2.2 上中下基础分区

```text
顶部 15% - 30%：标题 / 品牌 / 留白 / 巨大象征物
中部 45% - 65%：主角 / 载具 / 冲突现场 / 视觉爆点
底部 10% - 25%：角色名 / tagline / CTA / 商业信息 / Logo
```

竖版海报与横向封面最大的差别：

- 竖版允许标题更大、更像招牌。
- 竖版需要更强的上下方向视觉路径。
- 竖版可以用顶部留白制造高级感，也可以用顶部大字制造货架冲击。

## 3. 图形比例层：8 个常用构图模板

### 3.1 暗黑电影感 / 生存危机型

参考特征：背靠背人物、废墟、雾、灾难背景、克制标题。

```text
人物主体：45% - 70%
背景世界：40% - 70%
标题区：8% - 15%
雾气 / 空域：15% - 35%
装饰小字：3% - 8%
```

推荐比例：

```text
人物 55% / 环境 35% / 文字 10%
```

适合：恐怖、生存、末世、警匪、灾难、悬疑。

关键：人物可以暗，但轮廓必须清楚；背景必须讲故事，而不是纯纹理。

---

### 3.2 电竞赛车 / 高能潮流型

参考特征：巨大标题、斜切闪电、霓虹撞色、角色或载具冲出画面。

```text
大标题：20% - 35%
主体角色 / 载具：45% - 70%
斜切图形 / 速度线：20% - 40%
装饰信息：5% - 15%
```

推荐比例：

```text
标题 25% / 主体 55% / 速度线与装饰 20%
```

适合：赛车、MOBA、科幻竞技、潮流角色、赛季活动。

关键：斜线不是装饰，它必须参与构图，把视线从顶部压到主体再甩向底部角色名。

---

### 3.3 极简巨物剪影型

参考特征：小人物、大世界、单色背景、巨大隐喻物。

```text
大留白：35% - 60%
小人物：5% - 18%
巨大象征物：40% - 80%
标题：5% - 12%
```

推荐比例：

```text
留白 45% / 巨大符号 40% / 小人物与标题 15%
```

适合：开放世界、冒险、奇幻、文学化游戏、独立游戏。

关键：人物越小，世界越大；留白不是空，是压迫感和呼吸感。

---

### 3.4 群像拼贴 / GTA 式世界观型

参考特征：中心 Logo，多分格人物、载具、城市、动物、场景碎片。

```text
中心 Logo：20% - 35%
周边分格：65% - 80%
主角色 / 主场景锚点：25% - 40%
次要图块：每块 8% - 18%
```

推荐比例：

```text
主视觉 40% / 分格信息 40% / 标题 20%
```

适合：开放世界、多角色、多玩法、城市犯罪、商业宣发合集。

关键：分格可以多，但不能平均。必须有一个最大视觉锚点和一个中心 Logo 锚点。

---

### 3.5 现代运动编辑 / 极简速度型

参考特征：白底、巨大字体、几何速度线、载具较小但方向明确。

```text
留白：30% - 70%
载具主体：画面宽度 25% - 55%
大字排版：20% - 50%
几何速度线：25% - 60%
```

推荐比例：

```text
留白 45% / 几何线 35% / 载具 20%
```

适合：F1、摩托、超跑、体育赛事、品牌联名。

关键：字和几何线可以比车更大；高级感来自克制和方向性。

---

### 3.6 休闲欢乐商业活动型

参考特征：中心爆光、圆润角色、群像、强 Logo、底部合作方 / 搜索框 / CTA。

```text
标题 / 活动名：18% - 30%
中心爆点：35% - 55%
角色群像：45% - 70%
底部商业信息：8% - 15%
```

推荐比例：

```text
标题 22% / 爆点主体 55% / 商业信息 13% / 边缘装饰 10%
```

适合：休闲游戏、联名活动、电商活动、节日投放。

关键：信息可以多，但必须围绕一个中心光源组织，不能铺散。

---

### 3.7 水墨高反差 / 负形压迫型

参考特征：米色背景、黑色大剪影、少量猩红、角色在巨大墨形前方。

```text
负形 / 大剪影：45% - 75%
核心人物：15% - 35%
标题与发行信息：10% - 18%
留白：20% - 45%
```

推荐比例：

```text
大剪影 55% / 人物 25% / 留白与文字 20%
```

适合：暗黑动画、反派主题、悬疑角色、艺术向宣发。

关键：黑色大形必须有明确轮廓，不是随机墨迹。

---

### 3.8 电影战斗 / 三层景深型

参考特征：前景遮挡物、中景战斗主体、远景巨物 / 火山 / 月亮 / 战场。

```text
前景：10% - 25%
中景主体：40% - 60%
远景世界观：20% - 40%
标题：8% - 18%
```

推荐比例：

```text
前景 15% / 主体 50% / 远景 25% / 标题 10%
```

适合：RPG、射击、动作冒险、开放世界、灾难战场。

关键：前景虚化负责镜头感，远景巨物负责规模感，中景主体负责点击动机。

## 8. 标准生产 SOP

```text
Step 0. 【准入门】检查素材清单（§0）：
        - 游戏名字 ✅ 必选
        - 广告语 ⬜ 可选
        - ICON 正方形 ✅ 必选
        - 游戏画面截图 ✅ 必选
        任一必选缺失 → 停下来索取，不允许执行 Step 1
Step 1. 读取游戏 DNA 卡与 gameplay_lock（DNA 卡基于 ICON + 截图建立）
Step 2. 选择画幅：9:16 / 2:3 / 3:4 / 4:5
Step 3. 选择 poster_archetype（8 个模板之一）
Step 4. 先填 proportion_layer：标题占比、主体占比、留白、动线、景深
Step 5. 再填 expression_layer：色彩、字体、光影、质感、商业信息密度
Step 6. 绑定 story_mode：时间点、角色任务、观众关系、冲突、结果导向
Step 7. 做 Fidelity 自检：风格 / 角色 / 玩法都 ≥85%
Step 8. 线性化成自然语言英文 prompt
Step 9. 追加负面风格锁与负面玩法锁
Step 10. 生成后复盘：实际图是否符合比例层与表现层
```

硬约束：

- **Step 0 不通过 → 后续步骤一律不允许执行（最强硬约束）**。
- 不允许先写"赛博 / 高级 / 电影感"这类表现词，再倒推构图。
- 不允许把横向封面构图直接裁成竖版。
- 不允许为了视觉冲击误导玩法类型。
- 不允许让装饰信息超过主视觉。
- 不允许在用户没提供游戏名字时，AI 自己根据图像识别去猜。
- **不允许把 Step 0 提供的 ICON 画进封面 / 海报画面；ICON 仅作 reference-only。**
- **不允许直接复刻游戏截图 UI（关卡菜单、底部导航、loading bar、手机框、截图外框）；截图仅用于玩法和风格 DNA 分析。**

## 9. 周期性喂图学习协议

后续每次用户继续喂海报图素材，按以下格式沉淀。

### 9.1 每批图先输出观察报告

```text
本批新增素材：N 张
新增类型：<是否出现新 archetype>
比例层新增观察：<只写占比、动线、留白、景深>
表现层新增观察：<只写色彩、字体、光影、质感、商业装饰>
是否需要升级 SOP：是 / 否
升级位置：<章节名>
```

### 9.2 反馈进化规则

当用户反馈"这个分类不准 / 这个比例不对 / 这个选项缺失 / 这套生成不好用"时：

1. 先定位是比例层问题，还是表现层问题。
2. 如果是比例层问题，优先改模板阈值或新增构图模板。
3. 如果是表现层问题，优先改色彩 / 字体 / 光影 / 质感选项池。
4. 如果是玩法误导，升级 `gameplay_lock` 与高危误导清单。
5. 每次修改必须写入本文 `变更记录`。

### 9.3 证据等级

| 等级 | 含义 |
|---|---|
| `observed` | 只在参考图中观察到 |
| `single-run` | 用该规则生成过一次 |
| `validated` | 多次生成 / 用户反馈有效 |
| `deprecated` | 被反馈推翻，不再推荐 |

## 10. 最终检查清单

每张竖版海报产出前检查：

- [ ] **【Step 0】游戏名字是否由用户文本提供（不是 AI 猜的）？**
- [ ] **【Step 0】ICON（正方形）是否提供？**
- [ ] **【Step 0】游戏画面截图（长方形）是否提供？**
- [ ] **【Reference-only】是否明确禁止把 ICON / 截图 UI 画进最终画面？**
- [ ] 是否明确画幅？
- [ ] 是否先填了比例层，再填表现层？
- [ ] 第一眼焦点是否明确？
- [ ] 主体占比是否匹配海报类型？
- [ ] 标题占比是否匹配商业目标？
- [ ] 是否有可解释的视觉动线？
- [ ] 是否有前中后三层，或明确选择了平面图形风格？
- [ ] 色彩是否控制在主色 / 辅色 / 点睛色？
- [ ] 字体人格是否服务题材？
- [ ] 质感是否统一，而不是随机叠脏？
- [ ] 背景是否在讲故事？
- [ ] 商业信息是否没有抢主视觉？
- [ ] 玩法 Fidelity 是否通过？
- [ ] 负面玩法锁是否覆盖高危误导？
