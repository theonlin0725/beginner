RQ>1：该游戏每一份流量换来的收入高于该国平均 → 流量给少了；RQ<1 反之。天然免疫规模差异。

3分国家品类供需分析 → 选品策略

供给=品类占用的流量/在架数量；需求质量=用户用留存和付费投出来的票（品类7留、ARPDAU 相对该国大盘的倍数）。质量高而供给少 → 加大供给；质量高供给足 → 保持；质量低供给多 → 收缩；质量低供给少 → 定向试点。

4方法论：为什么这样对比才科学

保证「不同规模的游戏可以放在同一张图上比效率」，是整套框架的地基。

1. 效率坐标只用比率，规模只做气泡

留存率、ARPDAU、人均时长都是"人均/比率"指标，天然与体量无关；活跃UV/注册UV 只映射为气泡大小。避免了"UV大的游戏收入总额也大 → 看起来更好"的伪结论。

2. 国家内对比，不跨国比绝对值

泰国 eCPM ≈ 印尼的 1.6 倍，跨国直接比 ARPDAU 会把"国家变现水位差"错当成"游戏好坏"。所以每张图的基准线是该国大盘加权均值，位置含义 = 相对本国平均的倍数。

3. 份额比消规模：RQ = 收入份额 ÷ 活跃份额

两个份额的分母都是本国大盘，相除后规模完全约掉。RQ>1 即"单位流量产出超过平均"，直接回答"流量给多了还是给少了"。

4. 留存只统计"可观测窗口"

7/27 注册的用户在 7/28 还看不到次留。次留只累计到 ≤07-26、7留只累计到 ≤07-20 的注册日，并按注册UV加权，杜绝近期"假0%"拉低平均。

5. 小样本熔断

30天活跃 <300 人日（约日均DAU<10）或注册 <100 的组合，比率抖动过大：图中降透明度、结论表标记「样本不足」，不参与加/减量建议，防止用噪声做决策。

6. 双指标交叉，防单指标误杀

留存×变现四象限：高留存低变现是"广告策略问题"（提变现），低留存高变现是"短线收割"（控量），二者动作完全不同——单看任何一个指标都会开错药方。

7. 新游豁免与生命周期标注

上线初期留存天然偏低（用户结构全是新用户）。近14天内新上架的游戏建议单独标注观察，不直接判"收缩"。本期 Mahjong Tile Match 即为放量爬坡期典型。

8. 品类聚合防辛普森悖论

品类指标一律按 UV 加权聚合，同时保留"在架游戏数"：某品类整体差可能只是被一款大盘子拖累，收缩前先看品类内部头部游戏是否健康。

5常态化 AI 分析 Skill 设计（可复制到其他 App）

把本页的口径固化为一个 AI Skill：丢入任意 App 的三张日表 CSV，自动产出同款分析页。
Skill 名称：minigame-traffic-analysis（小游戏流量分发与选品分析）

【输入契约】三张日表 CSV（字段名兼容映射，不强求完全一致）
  ① 注册指标表：日期 / 游戏名 / 品类 / 国家 / 用户类型 / 注册uv / 次留~30留
  ② 活跃指标表：日期 / 游戏名 / 品类 / 国家 / 用户类型 / 活跃uv / 人均次数 / 人均时长 / 滚动留存
  ③ 广告收入表：日期 / 游戏名 / 品类 / 国家 / 曝光 / 点击 / ecpm / 分成前后收入(USD)

【固定分析流水线】
  Step1 数据体检：日期覆盖、重复文件(MD5)、留存可观测窗口(次留≤T-1、7留≤T-7)、
        品类缺失率(>50%时启用游戏名规则推断并显式标注)
  Step2 聚合：游戏×国家×用户类型 30天聚合；比率指标一律UV加权
  Step3 效率指标：ARPDAU($/千DAU)、加权D1/D7、RQ=收入份额÷活跃份额、
        质量指数Q=0.5×(D7/国家大盘)+0.5×(ARPDAU/国家大盘)
  Step4 三大评估：存量四象限 → 新用户四象限 → 品类供需四象限
  Step5 动作映射（阈值可配）：
        存量: Q双高→加大分发 | 留存高变现低→提变现 | 留存低变现高→控量 | 双低→收缩
        新量: 次留≥大盘×1.1且份额<收入份额→新量加码 | 次留<大盘×0.8且份额高→新量削减
        品类: 质量≥1.05且供给份额<25%→加供给 | 质量≥0.95→保持 |
              质量<0.95且供给≥15%→收缩 | 其余→定向试点
  Step6 输出：暗色 ECharts 单页报告 + 动作清单表 + 待核实清单

【硬性护栏】
  - 效率对比只用比率指标，规模只做气泡大小
  - 一律国家内对比，基准线=该国大盘加权均值
  - 样本熔断：活跃<300人日 或 注册<100 不出加减量结论
  - 上线<14天的新游标注"爬坡期"，不判收缩
  - 所有推断字段（如品类推断）必须显式标注，不冒充事实
