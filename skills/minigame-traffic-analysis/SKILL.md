# minigame-traffic-analysis（小游戏流量分发与选品分析）

## 触发条件
当用户需要对小游戏/休闲游戏业务进行**流量分发效率评估**、**新用户分配合理性分析**、或**品类供需与选品决策**时触发。典型话术：
- "跑一遍游戏数据分析"
- "看看游戏流量分配合不合理"
- "哪些游戏该加量、哪些该减"
- "品类选品建议"
- "常态化游戏分析报告"

## 安装（分享给同事，3 步）

本 Skill 为**自包含包**（方法论 + 可执行脚本 + 本地 ECharts + 报告模板），同事拿到后无需联网、无需起服务。

## 运行命令参考

同事只需一条命令即可出报告（详见 README.md）：

```bash
python3 scripts/aggregate.py \
  --reg   注册指标.csv \
  --act   活跃指标.csv \
  --ad    广告日表.csv \
  --channel wetv \
  --countries 印度尼西亚,泰国,马来西亚,菲律宾 \
  --report report.html
```

| 参数 | 必填 | 默认 | 说明 |
|---|---|---|---|
| `--reg` | ✅ | — | 注册指标 CSV |
| `--act` | ✅ | — | 活跃指标 CSV |
| `--ad` | ✅ | — | 广告收入 CSV |
| `--report` | 否 | 不渲染 | 指定后直接产出 HTML 报告路径 |
| `--channel` | 否 | 未指定渠道 | 渠道名（仅报告展示用） |
| `--title` | 否 | `{channel} 小游戏...` | 报告标题 |
| `--days` | 否 | 30 | 分析窗口天数 |
| `--countries` | 否 | 自动 Top4 | 分析国家，逗号分隔；不填则按活跃量自动取前 N |
| `--top-n` | 否 | 4 | 未指定 --countries 时展示的国家数 |

**列名自动探测**：三张表的列名只要"包含"下列关键字之一即可被识别，无需改名：
日期 / 游戏名·appid / 国家·地区 / 用户类型 / 三级品类·品类 / 注册uv / 活跃uv / 次留率 / 7留率 / 人均在线时长 / 人均活跃次数 / 广告曝光pv / ecpm / 分成前收入。
英文常见列名（date / appid / country / region / dau / ret_d1 / ecpm / revenue 等）也已内置支持。

## 输入契约（三张日表 CSV）
用户需提供以下三张日表（字段名可映射，不强求完全一致）：

| 表 | 必要字段 | 说明 |
|---|---|---|
| **注册指标表** | 日期, 游戏名(appid), 品类(三级), 国家/地区, 用户类型(新用户/老用户/ALL), 注册uv, 次留率~30留率 | 新用户获取与注册留存 |
| **活跃指标表** | 日期, 游戏名(appid), 品类, 国家/地区, 用户类型, 活跃uv, 人均活跃次数, 人均在线时长/min, 次留率~30留率 | 存量用户活跃与滚动留存 |
| **广告收入表** | 日期, 游戏名(appid), 品类, 国家/地区, 广告曝光pv, 广告点击pv, ecpm, 分成前收入(USD) | 变现数据 |

> **注意**：如果用户提供的是 Excel(.xlsx)，先用 xlsx skill 转为 CSV 再处理。

## 分析流水线（6 步）

### Step 1 数据体检
- **日期覆盖**：确认三张表的日期范围是否一致，取交集作为分析窗口
- **重复文件检测**：MD5 对比，排除重复上传
- **留存可观测窗口**：
  - 次留只统计 `注册日期 ≤ 最大日期 - 1` 的记录
  - 7 留只统计 `注册日期 ≤ 最大日期 - 7` 的记录
  - 避免近期"假0%"污染加权平均
- **品类缺失率检查**：若三级品类缺失率 >50%，启用游戏名规则推断并显式标注来源（ⓘ 标记）

### Step 2 数据聚合（Python 脚本）
按 **游戏 × 国家 × 用户类型** 三维聚合 30 天数据：

```
核心输出矩阵：
├── matrix_all: 存量（ALL 用户口径）
│   ├── act_uv: 30天活跃人日累计
│   ├── avg_dau: 日均 DAU = act_uv / 天数
│   ├── dur: 加权人均在线时长 (min)
│   ├── times: 加权人均活跃次数
│   ├── d1/d7: 活跃口径滚动次留/7留 (UV加权)
│   ├── rev: 分成前广告收入 (USD)
│   ├── arpdau: ARPDAU = rev / act_uv × 1000 ($/千DAU)
│   ├── ecpm: 加权 eCPM (USD)
│   └── rq: RQ = 收入份额 ÷ 活跃份额 (国家内)
│
├── matrix_new: 新用户口径
│   ├── reg_uv: 30天注册UV累计
│   ├── reg_d1/reg_d7: 注册口径次留/7留 (注册UV加权)
│   └── share_reg: 注册份额 (国家内)
│
├── bench: 国家大盘基准（game=ALL 行提取）
│   └── 含该国加权平均的 d1/d7/arpdau/new_d1/new_d7/ecpm/reg_uv
│
└── cats: 品类聚合（游戏→品类 groupby + UV加权）
    ├── share_uv/share_rev/share_reg: 三份额对比
    ├── arpdau/d1/d7/dur: 品类级效率指标
    └── rq: 品类 RQ
```

**关键规则**：
- 所有比率指标一律 UV 加权，不可简单算术平均
- 品类映射优先使用数据自带三级品类；缺失时按游戏名规则推断（需标注）
- 排除 game="ALL"、country="ALL"、"未知" 的行（仅用于大盘基准）

### Step 3 效率指标计算

| 指标 | 公式 | 含义 | 规模无关？ |
|---|---|---|---|
| **ARPDAU** | 分成前收入(USD) / 活跃UV × 1000 | 每千活跃日产出 | ✅ 比率型 |
| **RQ** | (收入/本国总收入) ÷ (活跃UV/本国总UV) | 单位流量产出倍数 | ✅ 份额比 |
| **质量指数 Q** | 0.5×(D7/大盘D7) + 0.5×(ARPDAU/大盘ARPDAU) | 综合效率评分 | ✅ 归一化 |
| **新用户倾斜** | 注册份额 vs 收入份额偏离度 | 新量分配合理性 | ✅ 份额比 |

### Step 4 三大评估模块

#### 4.1 存量流量分发评估（S1）
- **四象限散点图**（每个国家一张）：
  - X轴: 7日滚动留存率 (%)
  - Y轴: ARPDAU ($/千DAU)
  - 气泡大小: 30天活跃人日（仅视觉，不参与坐标）
  - 虚线: 该国大盘加权均值
  - 分类逻辑:
    - 双高(留存≥大盘 & 变现≥大盘) → **加大分发**
    - 留存高变现低 → **提变现策略**（不动量）
    - 留存低变现高 → **控量观察**（短线收割）
    - 双低 → **收缩流量**

#### 4.2 新用户流量分配评估（S2）
- **四象限散点图**（每个国家一张）：
  - X轴: 新用户注册次留率 (%)
  - Y轴: 该游戏在该国的 ARPDAU（用 ALL 口径近似）
  - 气泡: 30天注册UV
  - 判定:
    - 次留 ≥ 大盘×1.1 且份额 < 收入份额 → **新量加码**
    - 次留 < 大盘×0.8 且份额高 → **新量削减**
    - 其余 → **保持/优化承接**

#### 4.3 品类供需与选品（S3）
- **供需四象限**（每个国家一张）：
  - X轴: 供给（品类活跃流量份额 %）
  - Y轴: 需求质量指数 Q（归一化到 1=大盘）
  - 气泡: 在架游戏数
  - 结论映射:
    - Q ≥ 1.05 且供给 < 25% → **加大供给**（引入同品类新游）
    - Q ≥ 0.95 → **保持**
    - Q < 0.95 且供给 ≥ 15% → **收缩**（淘汰长尾）
    - 其余 → **定向试点**

### Step 5 动作清单输出
每张图下方附带结构化表格，含：
- 游戏/品类名称、日均DAU、各份额、效率指标相对大盘倍数、**动作标签+颜色编码**

标签体系：
| 标签 | 颜色 | 含义 |
|---|---|---|
| 加大分发/新量加码/加大供给 | 绿色 #3ecf8e | 效率高且流量不足 |
| 保持 | 蓝色 #4d9fff | 表现正常 |
| 提变现/观察优化/定向试点 | 黄色 #f7c948 | 有潜力但需调策略 |
| 收缩/新量削减 | 红色 #ff6b6b | 效率低且占用资源多 |
| 样本不足 | 灰色 #8b98ad | 数据不够做判断 |

### Step 6 输出物
- **单页 HTML 报告**（暗色主题 ECharts）：
  - S0 大盘 KPI + 趋势 + 国家盘子
  - S1 存量四象限 + RQ柱 + 错配图 + 动作表
  - S2 新用户四象限 + 分配图 + 动作表
  - S3 品类供需象限 + 三份额对比 + 选品结论
  - S4 方法论说明（8 条科学对比原则）
  - S5 Skill 自身设计文档
- **待核实清单**：所有推断字段（品类推断等）单独列出

## 硬性护栏（不可违反）

1. **效率对比只用比率指标**，规模只做气泡大小 —— 绝对值对比会产生规模偏差
2. **一律国家内对比**，基准线 = 该国大盘加权均值 —— 跨国比绝对值会混淆国家水位差
3. **样本熔断**：30天活跃 <300 人日 或 注册 <100 不出加减量结论
4. **上线 <14天的新游标注"爬坡期"**，不判收缩
5. **所有推断字段必须显式标注**（ⓘ），不冒充事实
6. **留存只统计可观测窗口**，杜绝近期假0%
7. **品类聚合防辛普森悖论**：保留在架游戏数，收缩前先看头部健康度
8. **双指标交叉判定**：留存×变现二维交叉，防单指标误杀

## 可复用性设计要点

本 Skill 设计为**渠道无关、App 无关**的通用框架：
- 只依赖三张日表的标准字段，不绑定特定 App 或渠道
- 国家列表可配置（默认取 Top4 活跃国家）
- 品类体系可扩展（规则引擎式映射）
- 动作阈值可参数化（当前默认值已在 S4 方法论中注明）
- 输出为自包含 HTML（ECharts 本地化），无需外部服务
